Ray Caster
~~~~~~~~~~

256 brads for sin table
cos table is just +64 (&40) offset
heading is a brad for centre of screen
each vertical column direction is a brad either side
fixed point 8.8 for player position and vectors
ray starts at player position
for current ray get step in x, step in y from brad
step along ray by one unit each loop (add step x & step y to ray pos x & ray pos y)
use ray position as lookup into a map until in a cell that is non-zero
for height just do simple loop to calculate 40 / distance (num steps)
clip to max height
draw vertical line of sky / wall / floor
player can move one unit forwards or backwards along heading only

addsteptopos
            ldx #$02       ; do index of 2 so can step over consecutive lo/hi bytes
loop_stepadd
            lda stepx,x    ; & y
            ora #$7f       ; sign extend 8 bit step value to 16 bit
            bmi negative   
            lda #$00
			.negative
            pha			   ; high byte needs to be either $ff (negative) or $00 (positive)
            ;clc
            lda stepx,x    ; & y
            adc rayposx,x  ; & y
            sta rayposx,x  ; & y
            pla
            adc rayposxh,x ; & y
            sta rayposxh,x ; & y
            dex
            dex
            bpl loop_stepadd

suffers from fisheye effect as distance is calculated as number of steps along the ray
need that distance projected onto the heading vector
distance x cos(angle between them) - we know angle between is our brads as we step columns
we know this is reflected in central axis so only need 20 (max) scale factors
we have cos(angle) for each column as s.7 need to multiply distance as 8.8 by this to scale down
scale goes from &7F (1.0) to &71 (0.89) at end column, so just 4 bits of info.

Just sum up the scale factor N times and take that as new distance.

  - Decide how many "columns" we are going to have, e.g. 40, then step along top & bottom paths 40 times - this
    gives us (x,y) co-ordinates for a convex polygon that defines the extents of a column
  - Decide how many "rows" we are going to have, e.g. 8, divide up the polygon into 8 cells - these correspond to

    the minimum set of characters required to draw these polygons.
  - Generate code that renders a "column" on the screen by loading screen addresses, OR'ing or AND'ing appropriate
    pixels and writing back for each cell in order.
  - Should end up with 40x functions that map a byte of pixels to the screen in whatever pattern is determined by
    path fns.
